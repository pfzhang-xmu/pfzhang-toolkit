# 已确认贡献（Confirmed Contribution）

> 来源: PaperSpine Contribution-First 铁律。**无本文件且字段全填，不开始正文写作。**
> 规则: 每个单元格必须填写真实内容，禁止 TODO / TBD / … / 待定 / 无。『缺失证据』与『声称边界』是审稿人最看重的两格，缺一不可。
> 校验: `python toolbox.py contribution-check <项目目录>`，通过后再谈动机主线与各节写作。

## Core Contribution（核心贡献：本文唯一要证明、并愿意被审的第一句话）

| 字段 | 内容 |
|------|------|
| 主导贡献一句话 | （明确、可被证伪的单一声称） |
| 贡献类型 | new method / new dataset / new theory / new empirical finding / new system / new analysis-or-benchmark / new application |
| 审稿人记忆点 | （若审稿人只记得一件事，就是这句——写给领域的价值，不是"我们做了什么"） |

## Why This Contribution Is Needed（为什么需要这个贡献）

| 字段 | 内容 |
|------|------|
| 领域问题 | （这个领域为什么存在、人们在乎什么） |
| 具体缺口 | （缺的具体能力/知识；不是"X 研究不足"，而是哪一格的洞） |
| 具体挑战 | （为什么缺口难补——技术/实证障碍） |
| 先前为何解不了 | （点名最接近的已有方法，逐一说明各自为何没解决这个缺口） |

## How This Paper Responds（本文如何回应）

| 字段 | 内容 |
|------|------|
| 设计回应 | （针对上面"具体挑战"的核心想法/机制；用"因为是障碍Y所以用X"，而非"我们用了X"） |
| 所需证据 | （审稿人要相信主导贡献，会要求什么证据——先于检查你有什么） |
| 可用证据 | （你实际有的：实验/证明/数据/消融） |
| **缺失证据** | （"所需"减去"可用"的差距。若非空，主导贡献必须软化或补做；诚实填写防止过度声称） |

## Claim Boundary（声称边界：让贡献不被过度声称）

| 字段 | 内容 |
|------|------|
| 强声称允许 | （有"可用证据"充分支撑的声称，可满强度陈述） |
| 软化或避免 | （证据扛不动的声称，用 suggests/in this setting 或删掉） |
| novelty风险 | （审稿人最可能的"这已被 X 做过"质疑，诚实回答"和 X 差在哪"） |
| significance风险 | （审稿人最可能的"so what / 太窄"质疑，诚实回答） |

## 本节写作后果（每节该强调/避免什么）

| 章节 | 本贡献要求它强调 | 本贡献要求它避免 |
|------|------------------|------------------|
| 摘要 | 问题→缺口→承诺→证据→收益 五句契约 | 超出"强声称允许"的宽泛承诺 |
| 引言 | 漏斗：领域问题→进展→缺口→RQ→贡献承诺→证据预告 | 缺口的空话、与贡献脱节的泛述 |
| 方法 | 每个设计选择回扣"具体挑战" | 只描述不辩解为什么 |
| 结果 | 每小节测试一个引言承诺 | 无证据支撑的纯指标段 |
| 讨论 | 机制解释+回扣贡献+诚实局限 | 结果数字复读、空泛意义 |
