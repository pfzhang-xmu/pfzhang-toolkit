# 科研写作与审稿质量准则（从核心 skill 提炼）

> 用途: paper-pipeline 每个子代理在写作/审稿前必须读取本文件，确保语言逻辑、思维方式、表达习惯一致。
> 来源: nature-writing, write-scientific-manuscript, polish-prose, simulate-reviewers, nature-reviewer, scientific-prose-style 等。

## 一、写作逻辑（想清楚再写）

1. 每个段落只做一个主要任务。
2. 段落默认结构：主题句 → 必要背景 → 证据/推理 → 解释 → 连接下一段。
3. 先写科学逻辑，再润色语言；逻辑错了，改词没用。
4. 每个 Claim 必须能指到证据（图/表/数据/文献）；没有证据就写“待验证/推测”。
5. 观察与解释分开：`show` 用于直接证据，`suggest / is consistent with / may reflect` 用于解释。
6. 不要把相关性/预测/敏感性说成机制或因果。
7. 负面结果和局限必须保留，不能为了流畅删掉限定语。

## 二、表达习惯（像成熟研究者，不像 AI）

1. 主动语态优先（“We propose...”），被动语态只在程序/结果为焦点时用。
2. 删掉 AI 味词汇：delve, leverage, moreover 堆叠, Furthermore 连排, em dash 链。
3. 每段最多 1 个 em dash；摘要里不要用 em dash。
4. 一个句子一个主结论；避免抽象名词链（“the utilization of...” → “using...”）。
5. 术语统一：首次出现定义，后续一致；不要为了显得高级造词。
6. 强声称词（first, novel, state-of-the-art, significantly, comprehensive, robust, optimal）必须能被数据支撑，否则删/弱化。
7. 完成的事实不 hedged（“we propose”），解释/推广保留一个诚实的 hedge，双 hedge 合并。

## 三、结构规范

- **Title**: 直接给核心贡献/发现，不夸大广度。
- **Abstract**: 问题 → 未解缺口 → 方法 → 核心证据 → 有界意义；脱离正文可读。
- **Introduction**: 大问题 → 具体未解问题 → 为什么现有方法不够 → 本文做什么。
- **Results**: 先问题/目的 → 报告结果 → 适度解释；方法细节只在需要理解比较时出现。
- **Discussion**: 先主要进展 → 解释而非重复结果 → 对比前人 → 局限 → 具体意义。
- **Methods**: 精确可复现，不追求修辞；菌株/试剂/浓度/时间/统计全部明确。
- **Figure legends**: 不读正文也能懂；定义 panel、组、单位、n、误差棒、显著性、缩略语。

## 四、审稿人看什么（返修预防）

- P0: 数据缺失、方法不可复现、融合子/结果真实性无证据、统计缺失、学术不端。
- P1: 强声称无支撑、参考文献乱/跳号/缺卷期页、图表编号不对齐、Data Availability 不达标。
- P2: 语言 AI 味、标点/编码、术语不统一、可读性。
- 审稿人最讨厌：结论先于证据、首次/空白没系统检索、推广超出证据、占位符残留。

## 六、故事线（讲好一个故事）

一篇好文章是一个故事。各节有明确「故事任务」：

| 节 | 故事任务 | 读者应该得到什么 |
|----|----------|------------------|
| 摘要 | 预告片 | 问题→方法→结果→意义，脱离正文可读 |
| 引言 | 漏斗 | 大问题→具体缺口→贡献预告→路线图；末段知道「本文要干什么」 |
| 相关工作 | 给缺口铺证据 | 别人做了什么、还差什么（delta） |
| 方法 | 对白 | 可复现，不追求修辞 |
| Results | 正片 | 每节：目的→结果（数字/图表）→一句解释；证据跟着叙述走 |
| Discussion | 影评 | 进展→与已有工作对比→机制→局限→具体意义，不重复 Results |
| 结论 | 谢幕 | 一两句收束，不引入新证据 |

叙事纪律：
1. 先写摘要 5 句故事线（问题/缺口/方法/结果/意义），再展开各节——故事线不对，扩写必歪。
2. 一段一事：主题句先行，段落用内容衔接，禁止 Moreover/Furthermore/此外 堆砌。
3. 每个 Claim 挂证据（图/表/数据/文献）；show 与 suggest 分开。
4. 机器可查：`toolbox.py narrative_check`（摘要四要素/引言缺口与贡献/Results 证据密度/Discussion 回扣与局限/段落卫生），已接入质量门禁与 review-auto 第 5 步。

## 七、Contribution-First 三铁律（来自 PaperSpine）

1. **贡献先行**：动笔前必须有已确认的贡献（本文加什么、哪个问题/缺口使之必要、什么证据验证它、声称边界在哪、审稿人为何觉得可发表）。一句话论证模板：`In [系统/问题], we show [推进] using [方法], supported by [证据], with [边界]`——全文每部分服务这句话。
2. **Results 即验证**：每个 Results 小节必须验证至少一个贡献承诺；只有指标没有贡献映射的小节是失败的。
3. **审稿人意识**：声称"可投稿"前，从审稿人视角登记：价值图 + 反对意见清单 + 期刊契合度，逐条回应。

写作理由矩阵（framework/writing-rationale.md）：每个最小写作单元一行（≥8 行，首行全篇框架），含 动机链接/参考模式/期刊规范/证据锚点/计划动作/最终检查。**第四面墙**：矩阵与修改痕迹是内部规划，正文绝不允许出现「针对审稿意见」「重新组织」「初稿」等过程语言（机器查：quality-check process_leak）。

## 八、投稿前自检清单

- [ ] 无 [TBD] / [DATA REQUIRED] / ___ 占位符
- [ ] 所有 Claim 有对应图/表/数据/文献
- [ ] “首次/显著/可推广”均有系统检索或数据支撑
- [ ] 统计报告完整：n、均值±SD、检验名、p、效应量/CI
- [ ] 参考文献按首次出现顺序编号，卷/期/页完整
- [ ] Data Availability 指向公共仓库/accession
- [ ] 框架阶段至少规划 5 张图 + 3 张表，图表编号与正文引用一一对应，Figure legends 自明
- [ ] 无 AI 味表达，无 em dash 链，无空泛过渡词
- [ ] 已跑 `toolbox.py quality-check <项目>` 且无 P0/P1

## 九、机械纪律（机器可查，零容忍）

1. 禁止连续标点：`..`、`;;`、`,,` 一律视为缺陷，产出前自查消除；年份与卷期之间只用单分号或单逗号，禁止双分号。
2. 单句 ≤35 词，一句只做一个论断；摘要全文 ≤250 词。
3. 句首必须大写，不允许拼写错误；不确定拼写的专有名词（菌株名/化合物名/基因名等）按文献原文照抄，不得自造拼法。

## 十、引用纪律

1. 全文引文风格唯一（编号制或作者-年份制，以 journal/chosen.md 为准），禁止 `[1][2]` 与 `[1,2]` 两种形式混用。
2. 每个引文编号所在句必须陈述该文献实际证明的具体内容，不得挂空引用；外围/近缘物种文献必须用桥接句（先说明其与本文主对象的关联）引入，不得直接断言。
3. 参考文献每条必须字段完整：作者/年份/标题/期刊/卷/期/页码或文章号/DOI，缺字段的条目不得入库；et al. 的用法全文统一（截断规则一致）。
4. 引文编号按正文首次出现顺序递增，禁止跳号。

## 十一、投稿要素清单（submit 前逐项核对）

- [ ] Keywords 节存在，且关键词数量符合目标期刊要求
- [ ] 作者信息与单位真实完整，非占位符
- [ ] Data Availability 声明存在并指向数据所在处
- [ ] 页码/文章号、通讯作者标注按目标期刊要求落实

## 十二、模型档位纪律

1. flash（中等）档产出必须通过 `toolbox.py quality-check` 机器检查且无 P0/P1 才算完成，禁止以自述通过代替机器验证。
2. frontier（一等）档同样须过机器门禁，不得因档位更高而豁免检查。
